# Contributing

## Workflow
1. Create a focused branch for each change.
2. Keep commits small and descriptive.
3. Follow the frontend and backend guidelines.
4. Add or update tests for behavior changes.
5. Update documentation when routes, data models, configuration or user flows change.
6. Run the test suite before opening a pull request.

## Pull request checklist
- [ ] Scope and expected behavior are clear.
- [ ] Tests pass.
- [ ] No secrets or personal data are included.
- [ ] Authorization and validation are handled server-side.
- [ ] Documentation is updated.
- [ ] UI changes are responsive and accessible.
